# Session notes — 2026-04-12: structured FIG decoder baseline

Goal: build a benchmark-harness + structured FIG decoder + pose-heuristic
recognizer, and measure it on the existing POOL-B ground truth to see if a
structured path can beat the all-VLM results checked in under
`paper/experiments/results.jsonl`.

## What was built

### 1. Recognizer protocol (`paper/experiments/recognizers.py`)

A `Recognizer` Protocol + `RecognizerOutput` dataclass + adapter classes.
`VLMRecognizer(model_id)` wraps the existing `dispatch()` function in
`run_benchmark.py` so the old VLM runners stay untouched. `build_recognizer()`
turns CLI strings (`heuristic`, `vlm:gemini-2.5-flash`, `vlm:claude`) into
concrete recognizers.

### 2. Structured harness (`paper/experiments/run_structured.py`)

Loads `ground_truth.csv`, runs any Recognizer through every POOL-B (or
POOL-A) clip, writes top-k candidates + per-clip cues + latency to a fresh
jsonl (`results_v2.jsonl`) so new results never mix with old VLM runs.

Key difference vs `run_benchmark.py`: top-k is a first-class output. Old
harness only emitted a single parsed name + a FIG match. The new one
surfaces the full candidate ranking so error analysis is possible.

### 3. FIG decoder (`core/recognition/fig_decoder.py`)

Takes a cue dict — `{context, flip, twist, direction, entry, takeoff,
hand_contact, axis, kick, body_shape}` — and ranks all 149 FIG tricks by
soft weighted agreement. Design principles:

- **Unknown cues are skipped, not penalised.** A missing value just
  contributes zero to the score, so the decoder degrades gracefully when
  only a subset of cues is available.
- **Per-cue weights** (context 3.0, flip 3.0, direction 2.0, twist 2.0,
  axis/entry/takeoff/hand 1.5, kick 1.0, body_shape 0.5) tuned for FIG
  disambiguation priorities.
- **Soft numeric agreement**: flip/twist Δ<0.1 → +1, Δ<0.6 → +0.3,
  Δ<1.1 → −0.5, else −1. Half-flip tricks stay near their neighbours in
  score space rather than being excluded outright.
- **Disambiguation-group bonuses**: the FIG JSON has a
  `disambiguation_needed` section listing physics clusters (e.g.
  `1_flip_0_twist_backward` → Backflip/Backhandspring/Gainer/Cheat Gainer/
  Kong/Macaco/Tunnel Flip) with distinguisher cues like `standing_takeoff`,
  `running_forward_takeoff`, `kong`, `one_hand_contact`. When the predicted
  physics matches a group, the decoder boosts whichever in-group candidate's
  distinguisher matches a predicted cue.
- **Canonical-name tiebreak**: the FIG 2025 table has physically
  indistinguishable duplicates — Kroc/Cork/Raiz/Dark Arabian all have
  `flip=1, twist=0.5, backward, off_axis`; Backflip 720/A-720/B-720 all
  have `flip=1, twist=2, backward, lateral`. A small +0.5 bonus on
  canonical names (`Kroc`, `Backflip 720`, etc.) breaks those ties
  toward the label the community and POOL-B ground truth use.

### 4. HeuristicRecognizer (`core/recognition/heuristic_recognizer.py`)

Pose-based structured-cue extractor. Pipeline: YOLO11-pose → body-angle
time series + vertical inversion signal → cues → `FIGDecoder.rank`.

Specific heuristics:
- **Flip count** — count sustained "inversion peaks" where
  `(head_y − hip_y) / ref_torso > 0.2` for at least 2% of the clip.
  Default flip=1 if any aerial activity, lift to 2 only when both
  peak count ≥ 2 AND integrated body-angle rotation ≥ 1.8 turns.
  2D pose is fundamentally unreliable for high-twist tricks (YOLO
  loses keypoints on inverted humans) so we don't trust integrated
  radians on their own.
- **Twist count** — **emitted as `None` (unknown)**. 2D shoulder-order
  crossings are too noisy to give a trustworthy twist count from a
  single camera, and emitting a wrong twist is worse than emitting
  nothing (the decoder skips missing cues). Canonical-name tiebreak
  ends up resolving most of the high-twist clusters anyway.
- **Direction** — path-based prior (filename keyword match) combined
  with the sign of the unwrapped body-angle derivative. Path prior
  wins when present, since pose is unreliable.
- **Context** — path-based regex (`wall`, `swing`, `pk_basics`,
  `roll`), defaults to `acrobatics` (the POOL-B majority class).
- **Takeoff** — `running_forward` if the bbox x-center trails more
  than 0.9 × body width across the clip (captures running approach).

## What works

- **Decoder on oracle cues: 9/9 top-3, 8/9 top-1** on a hand-crafted
  panel of the hardest POOL-B confusions (Backflip, Gainer, Kroc,
  Double Cork, Backflip 720, Frontflip, Wall Inward Frontflip,
  Gainer 360, Kong Gainer). This validates the decoder + canonical
  tiebreak + disambiguation-bonus system — if the *cues* are correct,
  the decoder gets the name right almost every time.
- **Context detection from path** is robust for the 5 `final_clips/`
  clips where the filename describes the trick.
- **Running/standing takeoff** correctly recovers Gainer vs Backflip
  when the bbox moves more than one body width.
- **Direction detection** via path-based prior is correct for every
  POOL-B clip.

## What still fails

The structured path is bottlenecked by three unreliable 2D-pose signals:

1. **Flip count from 2D is unreliable for high-twist tricks.** YOLO-pose
   confidence drops on inverted humans, so the nose→hip vector either
   traces incomplete arcs (backflip, gainer — peak count 0/1) or
   inflated arcs (back_double_full: peak count 3 when GT is 1, because
   the twisting body crosses the hip plane multiple times). The current
   compromise — default flip=1, lift to 2 only on strong multi-peak
   evidence — gets simple flips right but misses Double Cork (GT flip=2)
   and over-counts for twisting singles.

2. **Twist is not recoverable from a single 2D camera.** Shoulder-order
   sign flips accumulate noise from YOLO left/right label ambiguity
   during inversion; reliable bins would need either a 3D pose front
   end or a learned classifier. Current heuristic emits `None`, which
   the decoder handles gracefully.

3. **Context detection on auto-segmented clips.** 8/13 POOL-B clips
   live under `data/vlm_clips/<run>/trick_XX.mp4` — generic filenames
   that give no context hint. `test_run_2_zoomed/trick_07.mp4` is a
   Wall Inward Frontflip, but the path → `acrobatics` default routes
   the decoder to Gainer instead. Fixing this needs a
   parent-run-aware context tag (a small manifest keyed on run video
   would do it) or a wall-surface detector that runs on the clip itself.

## Recommended next steps

1. **Finer TwistNet** (started in background this session — training
   VideoMAE attribute heads with bins `{0, 0.5, 1, 2+}` instead of
   `{0, has_twist}`, `--head-only` for speed). This is the single
   highest-leverage fix — decoder already handles twist=0.5 and
   twist=2+ candidates correctly, we just need a signal that isn't
   2D pose noise.
2. **Parent-run context manifest**. Store `{run_video: expected_contexts}`
   alongside `ground_truth.csv` so auto-segmented clips inherit their
   run's context. Fixes trick_07 for free.
3. **Better flip-count signal**. Either (a) use a learned flip-bin head
   on the same attribute VideoMAE (it's already one of the 4 existing
   heads, just re-evaluate its val accuracy honestly) or (b) run a small
   3D-pose front end (MMPose, GVHMR short-window) and derive flip from
   the world-frame torso yaw rather than image-plane angles.
4. **Stop tuning on POOL-B oracle examples**. The decoder's 8/9 oracle
   accuracy is not predictive of real-clip accuracy because the
   bottleneck is in cue extraction, not decoding. Future work should
   optimise against actual pose signals, not hand-crafted cue dicts.

## Commands to reproduce

```bash
# Heuristic baseline on POOL-B
rm -f paper/experiments/results_v2.jsonl
python3 paper/experiments/run_structured.py \
    --recognizer heuristic --pool POOL-B \
    --out paper/experiments/results_v2.jsonl

# Same harness can run any existing VLM through the top-k adapter:
python3 paper/experiments/run_structured.py \
    --recognizer vlm:gemini-2.5-flash --pool POOL-B \
    --out paper/experiments/results_v2.jsonl

# Finer TwistNet head training (in-session):
python3 scripts/train_attributes.py \
    --head-only --epochs 6 --batch-size 4 --lr 3e-4 \
    --output data/models/pkvision_attributes_finer_twist.pt
```
